## 核心知识

### 1. 整幅画面只是一个距离场

这一版没有任何"物体"。没有网格、没有多边形、没有 sprite。画面里只有一件事：

```
D(p) = 到最近一滴液体的表面的距离   （内部为负，外部为正）
```

水滴、拉丝、水洼、字标、淹没全屏的水层，全都只是**往同一个场里丢 SDF**：

```python
def field_at(S, X, Y, cam, ...):
    acc = np.zeros((h, w), np.float32)   # Σ exp(-k·dᵢ)
    for ball in S["balls"]:  acc[bbox] += np.exp(-k * d_ball)
    for seg  in S["segs"]:   acc[bbox] += np.exp(-k * d_seg)
    for let  in S["letters"]:acc[bbox] += np.exp(-k * d_letter)
    if S["flood"]:           acc[...]  += np.exp(-k * d_flood)
    D = -np.log(np.maximum(acc, 1e-30)) / k
```

得到 D 之后，**着色根本不需要知道这是球还是字**——它只看到一个距离场。
这就是为什么字标可以被水"融掉一半"，为什么两滴相撞会自己长出脖子。

**这一条是整个项目的地基**：只要能把形状表示成距离，它就自动获得液态的所有行为。

### 2. 平滑并集：为什么是 log-sum-exp

普通的 `min(d₁, d₂)` 得到的是硬并集——两个球撞在一起会有一道锐利的交线。
要的是"粘"，所以用 log-sum-exp：

```python
D = -log( Σ exp(-k·dᵢ) ) / k
```

- `k → ∞` 时退化成 `min`（硬边）
- `k` 越小，融合范围越大（越"粘"）
- 这里 `k = 0.08`，特征宽度 `1/k ≈ 12.5 px`

它还有一个工程上的好处：**是可加的**。不需要排序、不需要两两配对，
每个形状各自往累加器里加一笔 `exp(-k·d)` 就行——天然可向量化，天然可并行。

参考实现用了一个带 max 的稳定版累加器（`fadd`/`fres`）。我把它换成朴素累加 + **距离截断**：

```python
w = np.exp(-K * np.maximum(d, -DCLIP))     # DCLIP = 240
```

因为 `exp(0.08×240) = e^19` 还在 float32 的安全区里，
而更深的内部（`d < -240`）反正早就饱和成"最厚的液体色"了。

### 3. 落地不是弹跳：液体的动能去哪了

第一版我做成了弹球——水滴落地压扁一下，然后抛物线弹起来再落回去。这是**固体弹性碰撞**的物理：动能被储存、再还回来。液体不是这样的。

参考的做法是：**落地之后永远不再离开地面**。

```python
SV_PUD = 0.52            # 静止水洼的竖直比例（扁透镜）
def sv_land(d, tl):
    s = 1.3 + (SV_PUD - 1.3) * spring(tl + 1.3/30, 6.0, d["z"])
    if s < SV_PUD:
        s = SV_PUD - (SV_PUD - s) * 0.45      # 过冲减半，避免"热狗"翻边
    return s
```

`sv` 是竖直半径比例：落地瞬间 1.3（压扁），`spring` 振荡几次后收敛到 **0.52**——一个高只有半径一半的扁透镜。水平半径取 `r/sv`，体积守恒。

那个 `if s < SV_PUD` 分支很关键：spring 会过冲到 0.52 以下，不过冲减半的话水洼会翻成"热狗"形状。

**那动能去哪了？** 全部交给溅射：

```python
ra = d["r"] * 0.16 * (1 - 0.3*|c|)     # 触须根部
rm = ra * lerp(0.55, 0.42, pinch)      # 中段（掐断时更细）
rt = rm * lerp(0.80, 0.035, pinch)     # 顶端（掐断后收成尖）
```

每滴落地长 5–7 根触须，从溅射体顶部内缘长出、用 `flung` 甩出去、顶端鼓成珠；`tDet` 时刻**掐断**——断下来的珠变成弹道小液滴飞走，触须本体用 `spring` 回缩（负瓣就是回弹鼓包）。

于是"溅起来"这件事有了完整的因果链：**压扁 → 长触须 → 顶端鼓珠 → 掐断 → 小液滴飞走 → 触须回缩**。

合并也一样：三摊水不是"滑"向中心，是**跳**过去的（0.34 秒的弹道）；合并后的半径**按面积相加**：

```python
def mass_r(t):
    a = DROPS[3]["r"]**2
    for h in HOPS:
        a += DROPS[h["who"]]["r"]**2 * sstep(h["tc"]-0.02, h["tc"]+0.16, t)
    return math.sqrt(a)          # √(56²+46²+42²+74²) = 112
```

不是 56+46+42+74 = 218。**半径相加会让球大得离谱**——这是"看起来像气球"的另一个来源。

最后，合并进来的水没有消失：它们在球体内部继续绕转，作为**只贡献颜色、不进距离场**的 ghost：

```python
S["ghosts"].append((960 + cos(a)*0.40*R, cy + sin(a)*0.34*R, ..., u, 0.85*kk))
```

`field_at` 里单独累加一个权重和色相，最后 `U = U*(1-gw) + gu*gw`。**这才是大理石纹的真正来源**，比在着色器里做域扭曲更省，也更有物理依据。

### 4. 厚度定色：薄的地方暖，厚的地方深

距离场的负值就是**液层厚度** `x = max(-D, 0)`。颜色完全由它驱动：

```python
body = mix(palThin(u), palMid(u), sstep(0, 5, x))
body = mix(body, palDeep(u), sstep(40, 260, x) · …)
```

三段调色板各自是一条"橘 → 洋红 → 紫"的渐变（`u` 是每个形状自带的色相参数）：

| | 起点 | 中 | 终点 |
|---|---|---|---|
| `palThin`（薄） | 1.00, 0.74, 0.30 | 1.00, 0.50, 0.66 | 0.84, 0.52, 1.00 |
| `palMid`（中） | 1.00, 0.36, 0.06 | 1.00, 0.10, 0.44 | 0.56, 0.12, 1.00 |
| `palDeep`（厚） | 0.80, 0.10, 0.04 | 0.62, 0.02, 0.30 | 0.24, 0.04, 0.60 |

于是**厚度自己会画出一圈轮廓**：边缘薄 → 亮暖，中心厚 → 深饱和。
不用描边、不用内阴影，边缘光是从物理量里长出来的。

字标四个字母的 `u` 是 `[0.05, 0.30, 0.55, 0.85]`——橘、粉、粉紫、紫。

### 5. 从 SDF 到法线：把距离场当成一座山

有了厚度 `x`，把液体表面当成一座**球冠状的小山**：

```python
h0 = sqrt(2·R·x + 2·R·0.6)      # R = 95，球冠近似
th = tanh(h0 / Hc)               # Hc = 210，让高度饱和
h  = Hc · th
dhdx = (1 - th²) · R / h0        # dh/dx
gh = -dhdx · grad(D)             # 水平方向的坡度
n  = normalize(-ghx, -ghy, 1)    # 法线
```

关键在最后一行：**梯度直接来自距离场的梯度**。
SDF 的梯度本来就是"指向最近表面的单位向量"，所以法线几乎是白送的。

有了法线，剩下全是标准着色：

- **漫反射**：`body · (0.26 + 0.50·(0.5+0.5·n·L)) · (0.50 + 0.50·n.z)`
  最后那个 `n.z` 因子让边缘变暗——**光泽感而不是橡胶感**
- **透射月牙**：背光侧的内缘压出一道饱和亮弧
  （光穿过液体、在反方向聚焦——液体看起来"透"就靠它）
- **菲涅尔**：`fr = 0.04 + 0.96·(1-n.z)⁵`，然后和影棚反射混合

### 6. 影棚：液体好看是因为它反射了一个精心布置的房间

反射方向 `r = reflect(-V, n)` 打进一个假想的摄影棚：

```python
c  = 暗梅子底色 (0.10, 0.03, 0.12) · 0.5
c += 顶部补光 (0.60, 0.40, 0.75) · 0.55·up²
c += 暖地板反弹 (1.0, 0.30, 0.32) · 0.32·ss(0.2, 0.95, dn)
c += 主柔光箱 (1.0, 0.97, 0.93) · 30.0 · softRect(…)   ← 强度 30
c += 右上小柔光箱 · 12.0                                ← 第二个高光点
c += 右侧条光 · 14.0                                    ← 拉长的条状高光
c += 左下 kicker · 4.0
c += 掠射边缘光 · 用场景色而不是白
```

**那个 30 倍的主柔光箱是全场最亮的像素来源**——它落在液体表面就成了那一小块刺眼的高光。
高光点（catch-light）之所以"点"，是因为柔光箱在反射空间里是一块有软边的矩形（`softRect`）。

液体的高级感有一大半来自这里：**它不是"有光泽"，而是"反射了一个真实的房间"**。

### 7. 字标也是距离场

字标不是贴图，是从字体栅格化出来的 SDF 纹理，和其他形状一起进同一个融合场：

```python
tx = (X - cxl)/scale + w/2       # 世界 → SDF 图坐标
sd = 双线性采样(letter_sdf, tx, ty)
dl = sd · scale - grow           # grow < 0 收缩，> 0 膨胀
acc += exp(-k · dl)
```

`grow` 就是"字母在融化/凝固"的那根旋钮——落位时它从 **−110** 收到 **0**，
四个字母一开始是一坨互相吞掉的液体，慢慢才"认出"自己是 d、r、o、p。

**踩过的坑（值得单独记）**：切字母 SDF 时不能用 `PIL.textbbox` 的边界。
它给的是**排版边界**，比墨迹窄——裁进字形内部之后，
`sample_bilinear` 的 clamp 会让那个负距离沿着图的边界**无限延伸**，
字母直接变成一个方块。正确做法是用**列投影**找墨迹段：

```python
colsum = (mask).sum(axis=0)
# 连续的 colsum > 0 段 = 一个字母
```

### 8. 水淹：两个波前之间的带

决堤那一秒（4.0–4.42s），液体不是一个球，而是一条**带正弦波前的宽带**：

```python
a = Y                                    # 沿传播方向的坐标
b = X                                    # 横向坐标
wave = A·(0.58·sin(b·f+ph) + 0.30·sin(1.87·b·f+…) + 0.14·sin(3.13·b·f+…))
dF = (a - (front + wave)) / sqrt(1 + wave'²)      # 前波前
dB = ((back + wave·0.85) - a) / sqrt(1 + …)        # 后波前
d  = 平滑最大值(dF, dB)                            # 两个波前取并集
```

三层不同频率的正弦叠加，得到不规则的波前；`sqrt(1+wave'²)` 是**弧长修正**——
波前越倾斜，它到某点的距离就越长。少了这一项，波前会变成一条僵硬的直线。

水淹没全屏后，液层厚度达到 2000+，于是 `palDeep` 接管，
再叠上"深部大理石纹"（域扭曲的色带）和碳酸气泡。

> **大理石纹的频率必须压得很低。** 参考用噪声函数，梯度平缓；
> 我第一版照抄系数换成正弦，结果得到一堆 10px 宽的细纹——像指纹不像大理石。
> 正弦的梯度是"振幅 × 频率"，比真噪声陡得多。

### 9. 相机：把"场"放到世界坐标里算

参考的相机是一条 Catmull-Rom 曲线（zoom + 中心点），开场 5.4 倍特写、最后回到 1.0：

```python
Xw = (屏幕x - 960)/zoom + cx
Yw = (屏幕y - 540)/zoom + cy      # 世界坐标网格
```

**最要紧的一条：SDF 必须在世界坐标里算，不能在像素坐标里算。**

因为融合半径 `k` 是世界单位。如果在像素空间算，镜头一推近（zoom 5.4），
同一个 `k` 在屏幕上的融合范围就缩小 5.4 倍——水滴会突然不再粘在一起。
反过来在远景又会糊成一团。**液体的物理性质不能随镜头变化。**

同理，阴影也不用真的再算一次场：`field(p - so)` 的一阶泰勒展开就是
`D - (Gx·24 + Gy·32)`，一次全屏乘加就够，省掉一次完整 SDF。
（符号别搞反——光在左上，影子就该落在右下。我第一版就写反了。）

## 叙事时间轴（150 BPM / 10 秒）

| 时间 | 事件 |
|---|---|
| 0.0s | **倒水**：macro 特写，上方垂下一条细流 |
| 0.167s | 流断开：上半截回抽，下半截落成水珠 |
| 0.4 / 0.8 / 1.2 / 1.6s | **四滴**依次砸下：压扁成扁透镜 + 溅出 5–7 根触须皇冠，顶端掐断成小液滴飞走 |
| 2.0 / 2.4 / 2.8s | **融合**：三摊水弹道跳进中心，半径按面积相加（√Σr²），合并进来的水在球内绕转 |
| 3.2s | **跃起**：整摊水跳起来（顶点 3.6s） |
| 4.0s | 落回、溅射 |
| 4.035–4.42s | **决堤**：波前从中路扫出，淹没全屏 |

| 4.50–6.4s | **凝固**：四个字母从 −70 的膨胀态收到 0，慢慢"认出"自己是 d、r、o、p |

## 运行

```bash
# 关键帧预览
python make_liquid.py preview

# 单帧
python make_liquid.py one 6.5 frame.png

# 全部 600 帧（多进程；约 4 秒/帧，2 并发约 20 分钟）
python make_liquid.py all 2

# 只渲某一段
python make_liquid.py range 270 600 2

# 编码
ffmpeg -y -framerate 60 -i frames/f_%04d.png -c:v libx264 -preset slower -crf 18 \
       -pix_fmt yuv420p -movflags +faststart output.mp4
```

值得玩的参数：

- `K`（0.08）——融合锐度。调到 0.03 所有东西会糊成一坨，调到 0.3 变成一堆独立的球
- `WORD_U` 的四色相——换一组就是另一套液体
- `FIELD` 的 `Hc`（210）——高度场的饱和高度，调小液体会更"薄"
- `CAM` 表——整片的运镜节奏

## 工程注记

**性能**（这台机器：24 核 / 可用内存 1.3–1.8 GB）：

| 阶段 | 耗时 |
|---|---|
| SDF 场（全屏，含所有形状） | 0.47 s |
| 液体着色 | 0.16 s（水淹时 2.3 s） |
| 背景 | 0.27 s |
| bloom | **1.65 s → 0.45 s** |
| 整帧 | 5.1 s → **3.9 s** |

bloom 原来是全屏做 6 级上采样，占了整帧 1/3。改成**在 1/4 分辨率上做多级、
最后一次性上采样**——bloom 本来就是模糊的，1/4 分辨率完全够用（参考走的也是 mip 链）。

三个坑：

- **SDF 必须在世界坐标算**（见第 8 节）。这是这一版最容易错、错了最难查的一条：
  画面在 zoom=1 时看起来完全正常，一推近就全乱。
- **字标 SDF 不能用 `textbbox` 裁**（见第 6 节）。裁窄了字形会变方块。
- **大理石纹的正弦频率要压到参考的 1/5**（见第 7 节）。正弦 ≠ 噪声。

另外 `scipy.ndimage.distance_transform_edt` 用来做字形的距离变换，
只在启动时算一次（0.95 s），之后每帧只是采样。

**内存是这个项目真正的天花板**（不是 CPU）。全屏 SDF 每帧的峰值分配很凶，
第一版跑 3 并发时，进程会在第 333 帧左右因为"分配不出 7.9 MB"直接崩。
两处修：

- `shade` 改成**按行分 216 行的条带**处理（见上文），峰值降到 1/5
- `mp.Pool(workers, maxtasksperchild=6)` —— 每渲 6 帧换一个干净进程。
  进程跑久了内存碎片会累积，重试也没用，只有换进程才行

最后用 **2 并发**：24 核在这台机器上完全用不满，瓶颈从头到尾都是那 1.3 GB 可用内存。
