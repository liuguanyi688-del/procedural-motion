## 核心知识

### 1. 三个数字定死一切：20 拍 / 120 BPM / 120 px

整片的所有时间都从这三个数推出来：

```python
BPM  = 120
BEAT = 60 / BPM        # 0.5 s
M    = 120             # 网格模块（px）
DUR  = 20 * BEAT       # 10.0 s  ← 片长不是"定"的，是算出来的
```

- 网格：横向 15 条线（x = 120…1800），纵向 9 条线（y = 60…1020），**全部落在 120 的倍数上**。
  版面裁切框 `trim = (120, 60, 1800, 1020)` = 14 × 8 个模块。
- 所有图形坐标都是模块的整数倍：红圆心 (840,300) 半径 240 = 2 模块；黑柱 (1320,60) 宽 120 高 960 = 1×8；黄三角底边 600→1080 = 4 模块。
- **"严格"就是美感的来源**：一旦允许某个元素偏离网格 10px，包豪斯就散了。

网格线本身也是动画：每条线对（距中轴 d 个模块）在 `0.125 + d × 0.125` 秒落版——也就是**第 d 个十六分音符**，落版时是 3px 的黑色钢笔线，再用 0.2 秒松弛成 1.1px 的发丝线。8 个距离 = 8 个音符，网格是"画"出来的，不是"显示"出来的。

### 2. 分色版 + 挖空：印刷的核心语义

这是整个项目最重要的一条。真实印刷是**分色**的：黄、红、蓝、黑各一块版，分别上机，叠印成图。

```
版面 = 4 张 0..255 的墨量图（Y / R / B / K）
合成 = 纸色 × (Y墨比) × (R墨比) × (B墨比) × (K墨比)
     其中 墨比 = 油墨色 / 纸色      （不是乘油墨色本身！）
```

```python
col = PAPER
for ink in "YRBK":
    col = col * mix(1.0, INKC[ink] / PAPER, m[ink] * dens)
```

为什么要除以纸色：印刷是**减色**的，油墨吸收了纸的反射光。直接 `col * 油墨色` 会算成"纸是白的"；`col * (油墨色/纸色)` 才是"这张纸印上这个墨之后是什么颜色"。差别在浅色区域肉眼可见。

**但光有叠印还不够——必须挖空（knockout）**：

```python
def paint(self, ink, fn):
    S = 掩版(fn)
    for k in "YRBK":
        if k == ink: self.img[k] = max(self.img[k], S)      # 印上
        else:        self.img[k] = self.img[k] * (1 - S)    # 挖掉其他色版
```

不挖空会怎样：背面那张"黑底 + 三原色三角/方块/圆"，黑色底会把三个彩色的通道直接乘黑——三角变暗黄、方块变暗红。**我第一版就是这么错的**，画面一片死黑。

挖空也决定了绘制顺序：**后画的形状会挖掉先画的**。所以 `render_plates` 里 `draw_group → draw_outer → field → title → type → marks` 的顺序不能乱。

### 3. 套印不准：让"机器感"变成"印刷感"

四块版分别上机，永远对不齐。给每块版一个不同的微位移：

```python
rough = 手绘抖动噪声(±0.65px)               # 边缘的毛刺
offs = {
  'Y': rough + (spread, 0),
  'R': rough + ( 1.3, -0.9) * reg,
  'B': rough + (-1.0,  1.2) * reg,
  'K': rough + ( 0.5,  0.4) * reg,
}
```

`reg` 是一条随剧情走的曲线，这就是全片的"印刷机状态"：

| 时间 | reg / spread | 观感 |
|---|---|---|
| 0–6.5s | 1.0 | 正常套印，只有毛边 |
| 6.5–7.0s | 1.0 → 2.3 | 翻版时四色逐渐散开（画面越来越"花"） |
| 7.0s（reveal） | 0.15，并叠 1 帧 +12% 墨量 | **"啪"地砸回套准**，像压印 |
| 8.0–9.5s | 1.0 → 1.4 + spread 4.5px | 自由呼吸，四色慢慢散开 |
| 9.5s（lock） | 0.12，+10% 墨量 | 再次锁死套准，全片收尾 |

那个 1 帧的 +12% 墨量是"墨吻"（ink kiss）——只在单帧上生效，肉眼感觉是"重压了一下"。

### 4. 级联：整张海报变成卡片翻过去

6.0–8.0 秒，版面被拆成 240px 的卡片系统，四波涟漪依次扫过：

| 波 | 时间 | 动作 | 波前 |
|---|---|---|---|
| R1 | 6.0–6.25s | 正面 120px **瓷砖**各自绕中心旋转 90° | 从红圆心 (840,300) 放射 |
| R2 | 6.5–7.0s | 240px **卡片**绕横轴翻到背面 | 自左上 (120,60) 的对角线 |
| R3 | 7.2–7.32s | 背面 **立柱成对**错位一格，交替上下 | 自右向左 |
| R4 | 7.5–8.0s | 卡片绕竖轴**转回正面**，向画面中心收拢 | 自外向内 |

每张卡片的翻转是一个纯函数：

```python
u  = clamp((t - start - 波前距离 * spanK) / dur)
sc = cos(pi * ease(u))        # R2：+1 正面 → -1 背面
sc = -cos(pi * ease(u))       # R4：-1 背面 → +1 正面
aa = abs(sc)                  # 卡片的"张开程度"
back = sc < 0                 # 是否露出背面
sn = sqrt(1 - sc*sc)          # 侧面厚度
```

`aa` 的三个区间决定了画什么：

- `aa > 0.9995`：卡片完全正对或完全翻过 → 直接取正面/背面的墨
- `aa < 0.002`：卡片侧立（几乎看不见）→ 画**印刷床**（黑），不是纸——否则会露出一条纸缝
- 中间：**梯形透视**。远边收窄 `xs = 1 - 0.22·sn·(...)`，覆盖率 `cov` 由梯形边界决定，最后 `mix(床, 卡面, cov)`，并且卡片自身加 `1 - 0.2·sn` 的明暗。

**为什么床是黑的**：卡片翻到一半时，卡片之间的缝隙如果露出纸张，画面就会像"撕开的纸"；用黑色印刷床垫底，缝隙读起来是"机器的阴影"。

### 5. 填充场：空格子继承最近形状的形制

6.0 秒那一刻，版面还有很多空网格。如果只是让它们翻白，翻版就"空"了。做法是：

```python
# 在 drop 前一瞬把版面渲染一次，逐格采样判断是否为空
for 每个空格子:
    找最近的形状（按带权重的 SDF 距离）
    格子朝向该形状的那个角 → 以该角为圆心，画这个形状的"形制"
    # qd=四分之一圆  sq=小方块  semi=半圆  hst=半个三角  bar=半条
```

于是红圆周围长出一圈红色四分之一圆，黄三角附近长出黄色半方，黑柱旁边长出黑条纹。**翻版不是"碎掉"，而是"这张海报把它的语法复制到了每一个空格子里"**。

### 6. 12 齿擒纵：把缓动量化为机械齿

3.25–4.0 秒，中央 8×8 模块整体旋转 −90°。直接缓动太"滑"，要的是**机械感**：

```python
x = ease(t) * 12                  # 12 个齿
k = floor(x); f = x - k
angle = -90 + 7.5 * (k + ease(clamp((f - 0.35) / 0.65)))
```

每个齿是 7.5°：前 35% 停住不动，后 65% 走完这一齿再停。12 齿 × 7.5° = 90°。
**齿的落点正好对上音轨里的棘轮声**（`ratchet` 用的是缓动函数的反函数 `io2_inv(k/12)`）——视觉的"卡"和听觉的"嗒"是同一条曲线算出来的。

### 7. 纸张、颗粒、抖动

```python
paperBase = (241, 233, 218)                    # 米白
tooth = 纸纹亮度 - 0.82                         # 纸张的纤维起伏
col = paperBase * (1 + tooth*0.30 + 大尺度噪声*0.018)
col *= 1 - 半径² * 0.10                         # 暗角
col += 颗粒 * 0.045                             # 逐帧种子的胶片颗粒
col += 三角抖动 / 255                           # 消色带
```

另外还有一道"网格避让"：`col *= 1 - g*(1 - 墨量)` —— 网格线只在**没有墨的地方**才显示。这样网格看起来是"印在纸上的辅助线"，而不是"浮在图形上面的图层"。这一行是廉价但极其有效的细节。

## 运行

```bash
# 关键帧预览
python make_bauhaus.py preview

# 单帧
python make_bauhaus.py one 7.9 frame.png

# 全部 600 帧（多进程；内存紧就调小并发数）
python make_bauhaus.py all 3

# 编码（这一版颗粒很重，crf 19 是体积/质感的平衡点；要更锐用 17，体积约 3 倍）
ffmpeg -y -framerate 60 -i frames/f_%04d.png -c:v libx264 -preset slower -crf 19 \
       -pix_fmt yuv420p -movflags +faststart output.mp4
```

值得玩的参数：`INKC` 的四色（换成别的配色立刻是另一套印刷厂）、`registration()` 里的 `reg/spread` 曲线、`RP` 四条涟漪的 `start/dur/span`（把 `span` 调大就变成很慢的"波浪式翻版"）、`M`（网格模块，改 160 会得到更松的版式）。

## 工程注记

印刷合成是**逐条带**（240 行）算的：坐标网格、分色版位移、卡片几何、墨量合成全在条带内完成，峰值内存只有几十 MB。这是在这台可用内存常年 1.3–1.8GB 的机器上跑 600 帧 1080p 的前提。

两个 Pillow 坑：

- `ImageDraw.text` 的默认锚点是 **"la"（顶部）**，不是基线。竖排文字用 `anchor="ls"`（左-基线）才不会画出画布。
- `ImageDraw.bitmap()` 对 `L` 模式不可靠，直接用 `paint_mask()` 传遮罩更稳。
