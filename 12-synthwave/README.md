## 核心知识

### 1. 位移镜头：地平线为什么在 615 而不是 540

画面高 1080，但地平线不在正中，而在 **y = 615**（下移 75px）：

```python
SHIFT   = 75
HORIZON = H / 2 + SHIFT          # 615
FPX     = (H / 2) / tan(FOV / 2) # 1158：焦距（像素）
```

这叫**位移镜头（shift lens）**，建筑摄影里用来拍高楼不变形。它的效果是：**所有竖直线保持竖直**，同时把地平线压低，给天空留出更多空间。相机并不"抬头"，只是成像面平移了——所以网格的灭点还在画面中心，但地平线在下面。

每个像素的光线方向就是：

```python
d = normalize((px - 960, HORIZON - py, -FPX))     # 再叠加俯仰 rx / 偏航 ry
```

### 2. 速度曲线 → 相机位置：积分而不是"打关键帧"

相机不是按关键帧移动的，而是按**速度曲线**推进：

```python
def speed(t):
    if t < 1.0: return 18 + 4*t          # 起步
    if t < 2.0: return 22 + 26*smooth(t-1)   # 提速
    if t < 2.6: return 48                # 巡航
    if t < 3.8: return 48 + 13*smooth((t-2.6)/1.2)  # 冲刺
    if t < 4.2: return 61 - 35*smooth((t-3.8)/0.4)  # 磁带拖拽：急刹
    return 34 + 30*exp(-(t-4.2)*2.4)     # 撞线后回稳
```

位置用**梯形积分**预计算成表：

```python
ZT = [0]
for i in range(N):
    z -= 0.5 * (speed(t) + speed(t+dt)) * dt     # 梯形法
```

好处：改速度曲线就等于改整条相机轨迹，而且**所有物体的"何时经过相机"都能反解**——棕榈树的位置就是 `camZ(经过时刻 + 0.22)`，保证它恰好在那个节拍从镜头边掠过。

### 3. 天空：渐变 + 星场 + 地平线热光

```python
pxa = e / fwidth(e)      # e = 光线的 y 分量；换算成"地平线以上多少像素"
```

用**像素距离**而不是角度来做渐变，这样无论 FOV 怎么变，地平线附近的辉光宽度都是固定的像素数：

```python
c += HAZE * (exp(-upx/12) * 0.50 + exp(-upx/55) * 0.30)   # 双层辉光
c += vec3(1, .82, .96) * exp(-pxa*pxa/2.2) * 1.25          # 2px 的地平线热光
```

星场用**球坐标哈希**：把方向向量转成 `(方位角, 仰角)` 再乘 70，取整得到格子 id，每格一个星。闪烁用帧号做相位。大星（`h > 0.994`）额外画十字光芒。

### 4. 条纹落日：带子会滚动，宽度随高度变

太阳是一块正对相机的广告牌，位于相机前方 1150m 处：

```python
r  = length((p - sunCenter) / SUN_R)
w  = 0.38 - y                       # 越靠下越宽
ph = w * 8.5 - t * 0.55             # 相位：随时间向下滚动
gapF = clamp(w * 0.42, 0, 0.62)     # 带子宽度
gap  = smoothstep(gapF + aa, gapF - aa, fract(ph))
a    = disc * (1 - gap)
```

**"带子越往下越宽"是关键**：真实的条纹落日是这个比例关系，如果做成等宽就会立刻变成"百叶窗"。太阳的圆盘后面还有一圈品红辉光（halo），在圆盘外衰减。

太阳位置用屏幕像素偏移来定义：`sunY = camY + sunPx/FPX * SUN_D`，`sunPx` 从 −150 升到 +110（1.1–3.9 秒），最后再抬 16px。

### 5. 山脊：脊状噪声 + 逐列剪影

山是**脊状噪声（ridged noise）**——`1 - |noise|` 的叠加。普通 fbm 得到的是起伏的丘陵，`1-|noise|` 得到的是**尖锐的山脊**：

```python
def ridged(x, z):
    s = 0
    for o in range(5):
        s += a * (1 - abs(noise(x*f, z*f)))
        a *= 0.5; f *= 2.03
    return s
```

再乘一个**包络**：`env = smooth((|x|-150)/380) * (0.45 + 0.55*smooth((190-z)/380))`——中间低两边高，形成"山谷"，让落日在中间露出来。

投影到屏幕是逐列求剪影。做法是**把所有采样点按屏幕高度排序，然后取每一列的第一个**：

```python
order = np.argsort(sy)                       # sy 小 = 高
uc, first = np.unique(cols[order], return_index=True)
top[uc] = sy[order[first]]                   # 每列最高的那个采样
```

这等价于"从前往后画、只填第一次遇到的表面"，但完全向量化。网格纹理用真实的世界 u 坐标做竖线，用"远平面近似"把屏幕 y 映射回 v 做横线。

### 6. 无限网格地面：数值求导是抗锯齿的全部

地面是射线与 y=0 平面的求交：

```python
t = -camY / d.y                # d.y < 0 才命中
X, Z = camX + d.x*t, camZ + d.z*t
p = (X/2.5 + 0.5, Z/5.0)       # 网格坐标
```

**关键在 `fwidth`**。网格线在远处会密集到小于一个像素，如果不做处理就会变成一片摩尔纹噪声。所以要先算**每个像素跨越了多少个网格单元**：

```python
fw = max(|p(px+1, py) - p(px, py)|, |p(px, py+1) - p(px, py)|)
d  = |fract(p - 0.5) - 0.5| / fw      # 用像素单位表示"离线的距离"
fade = 1 - smoothstep(0.10, 0.42, fw) # 线宽超过 0.1 格就开始淡出
```

于是远处的线自然消失（因为 `fw` 变大），近处的线保持 1px 锐利。**这一行 `fade` 就是"霓虹网格"和"摩尔纹灾难"的分界线。**

另外两道：**线合并补偿** `far = (1-fade)*min(1, fw*3.2)`（已经合并的线保留平均亮度，让远处不至于全黑）、**暗带** `smoothstep(3,8,pxb) - smoothstep(18,30,pxb)`（地平线下方 3–30px 压暗，让地平线读成一条线）。

### 7. 磁带时间重映射：画面本身在"卡"

`sceneTime(t)` 把播放时间映射成场景时间，制造录像带的物理故障：

| 条件 | 效果 |
|---|---|
| 前 30 帧（t < 0.5s） | 强制 **15fps**——磁头还没锁定的追踪期 |
| 3.867–3.933s | **倒退 2 帧**（倒带） |
| 3.933–4.2s | 继续 15fps 拖拽 |
| 9.667s 之后 | STOP：走带以 0.5 倍速缓缓停下 |

注意这不只是"画面抖动"——**整个 3D 场景的时间都跟着回退**，所以太阳会倒着落、相机位置会回退。这是最像真磁带的一点。

### 8. VHS 后期：色度延迟是灵魂

模拟录像带最核心的一条：**色度信号的带宽远低于亮度**。所以：

```python
# 亮度用当前像素，色度用"过去"的几个像素
Y = luma(c0)
iq = Σ exp(-i*0.55) * chroma(p - i*2.6px) / Σw      # 色度横向拖尾
col = toRGB(Y, iq * 1.1)                             # 亮度锐利 + 色度糊
```

这一条就把"数字画面"变成了"模拟信号"。然后叠上：

| 效果 | 做法 |
|---|---|
| 行抖动 | `wob = (噪声(yTop*0.03) - .5) * (1.1 + 12*track)`，逐行水平位移 |
| 磁带撕裂 | 随机行号 `gRow` 命中 18% 时整行横移 8–40px（**整行，不是色块**） |
| RGB 分离 | 红通道右移、蓝通道左移 `spx` 像素 |
| 红溢色 | 红色通道额外向右做 4 抽头拖尾（品红饱和处最容易溢出） |
| 扫描线 | `mod(yTop, 3) < 1 → ×0.88` |
| 静噪 | `track < 1s` 时混入 42% 的雪花 |
| 暗角 | `1 - dot(q*vec2(.95,1.15), q*vec2(.95,1.15)) * .62` |

最后 0.13 秒是 **CRT 关机**：光栅先压成一条线（`uCrtX` 收缩），再缩成一个点（`uCrtY` 收缩），中间留一道热白线和一圈蓝白辉光。

## 运行

```bash
python make_synth.py preview        # 关键帧预览
python make_synth.py one 3.0 a.png  # 单帧
python make_synth.py all 5          # 全部 600 帧（本机可用内存紧张，5 并发是上限）

# 编码（VHS 的扫描线与颗粒很吃码率：crf 19 → 23MB，crf 23 → 12MB，crf 26 → 7.6MB）
ffmpeg -y -framerate 60 -i frames/f_%04d.png -c:v libx264 -preset slower -crf 23 \
       -pix_fmt yuv420p -movflags +faststart output.mp4
```

值得玩的参数：`HAZE`（雾色，换成青绿立刻是另一套配色）、`speed()` 速度曲线、`SUN_RPX`（太阳在屏幕上的半径）、`fade` 的淡出阈值（改小会让远处的网格一直亮到地平线）、`uTrack`/`uStatic`（磁带劣化程度）。

## 工程注记

**光线场只算一次。** 相机只有平移和微小俯仰/偏航，`(px, py) → 方向` 的映射每帧重建一次（1920×1080×3 个 float32 = 25MB），之后天空、太阳、山、地面全部复用同一份方向场。

**逐像素 float32 纪律。** 一帧要跑约 800M 次浮点运算，任何一个数组悄悄升成 float64 都会让内存翻倍并直接 OOM。`np.where(cond, 1.9, 0.7)` 这种"两个参数都是 Python 标量"的写法会返回 **float64**——必须写成 `np.float32(1.9)`。这是本次唯一一次 OOM 的原因。
